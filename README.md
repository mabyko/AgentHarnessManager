# Agent Plugin Manager

에이전트의 플러그인과 스킬·MCP·훅·지침을 한곳에서 확인하고 작업에 맞게 구성하는 개인용 macOS SwiftUI 앱을 목표로 합니다. 제품명은 2026-10-02 사용자 결정으로 **Agent Plugin Manager**로 확정했습니다. Codex와 Claude Code부터 지원합니다.

현재 구현은 실제 로컬 스킬 목록과 원문을 읽고, 작업별 스킬 구성을 저장하는 단계입니다. 스킬 파일은 변경하지 않습니다. 플러그인 설치·업데이트와 MCP·훅·지침 관리는 후속 범위입니다. 회색 바탕과 절제된 파란 강조색의 ‘차분한 작업대’ 시안을 사용하며 예시 보기와 가상 데이터는 앱에서 제거했습니다.

## 제품 방향

플러그인을 여러 기능을 함께 설치·배포하는 패키지로 다룹니다. Codex와 Claude Code 양쪽에서 사용하는 개념을 따르되, 단독 스킬·MCP 서버·훅·지침을 플러그인으로 바꾸거나 묶음 소속을 추정하지 않습니다. 저장소는 출처, 플러그인은 배포 단위, 작업 구성은 사용자의 선택입니다.

후속 사용자 흐름은 `플러그인 탐색 → 포함 기능·출처·호환성 확인 → 설치와 업데이트 → 작업 구성에 연결`입니다. 직접 등록한 단독 항목도 원래 종류와 설치 위치를 유지하며 같은 작업 구성에서 확인할 수 있도록 확장합니다. 플러그인에 포함된 항목은 소속을 표시하고 패키지 관리 경로를 안내합니다. 제공자 캐시의 내부 파일을 개별 이동하는 기존 스킬 변경 경로로 플러그인을 관리하지 않습니다.

다른 에이전트의 플러그인 채택이나 형식 통일은 전제로 삼지 않습니다. 에이전트별로 지원 종류·공식 설치/갱신 방법·확인 가능한 상태를 검증한 뒤 지원 범위를 추가하며 미지원과 미확인을 구분합니다. 추천·별점·공유 등 커뮤니티 기능은 후속 단계이고 실행 루프 관리는 범위 밖입니다. 공통 컨텍스트인 `AGENTS.md`·`CLAUDE.md`는 지침으로 별도 관리합니다.

이 방향은 [OpenAI 플러그인 구조](https://developers.openai.com/plugins/build/plugins)와 [Claude Code 플러그인 개요](https://code.claude.com/docs/en/plugins/overview)를 2026-10-02 확인한 결과와 사용자 결정에 근거합니다. 각 에이전트의 플러그인 구성과 동작이 같다는 뜻은 아닙니다.

제품명과 기술 식별자의 전환은 분리합니다. 현재 Xcode 프로젝트·scheme·앱 파일 이름은 `AgentSkillManager`, 설치 앱 표시 이름은 ‘스킬 작업대’이며 Bundle ID와 설정 도메인도 기존 값을 사용합니다. 다음 프로젝트 이름 전환 때 기존 설치본과 사용자 설정의 연속성을 함께 확인합니다.

## 네이티브 앱 실행

macOS 26 이상과 Xcode 26 이상이 필요합니다. Xcode 27.0 / Swift 6.4 / macOS 27.0.1에서 검증했습니다. 외부 Swift 패키지 의존성은 없습니다.

```sh
open AgentSkillManager.xcodeproj
```

`AgentSkillManager` scheme을 선택해 실행합니다. 프로젝트를 다시 생성할 때만 설치된 XcodeGen이 필요합니다.

```sh
xcodegen generate --spec project.yml
xcodebuild -project AgentSkillManager.xcodeproj -scheme AgentSkillManager -configuration Debug -derivedDataPath /tmp/agent-skill-manager-derived build
swift test --package-path Packages/SkillCore
scripts/check-app-state.sh
```

| 위치 | 역할 |
| --- | --- |
| [AgentSkillManager](AgentSkillManager) | 단일 메인 창, 설정, AppStore, SwiftUI 화면과 테마 |
| [SkillCore](Packages/SkillCore) | 등록 위치 탐색과 안전한 SKILL.md 원문 읽기, 임시 폴더 통합 테스트 |
| [project.yml](project.yml) | Xcode 프로젝트 생성 명세 |
| [Base.xcconfig](Config/Base.xcconfig) | 개발용 식별자와 표시 이름, 로컬 서명 설정 포함 지점 |

현재 앱은 `~/.agents/skills`와 `~/.claude/skills`를 자동으로 확인합니다. 설정(⌘,)에서 두 에이전트의 스킬 폴더 상태와 추가 경로를 관리합니다. 폴더 선택은 SKILL.md가 있는 폴더 또는 스킬들을 모아 둔 폴더를 직접 등록하며, 경로는 앱별 UserDefaults에 저장해 재실행 후 복원합니다. 다른 에이전트는 이름과 경로를 수동 등록해 SKILL.md를 조회할 수 있습니다. 에이전트 설치·실제 로딩·다른 형식의 호환성을 확인한 것은 아닙니다. 등록 해제는 설정만 지우고 원본 파일을 건드리지 않습니다. 전체 프로젝트 발견 규칙과 물리적으로 동일한 루트 합치기는 후속 범위입니다.

설치 목록은 이름·위치 검색, 에이전트 필터, 링크 조회, 발견 위치별 누락·접근 실패·부분 결과를 제공합니다. 같은 이름의 복사본과 링크는 별개 항목입니다. 등록 위치 밖 링크의 본문은 읽지 않으며 일반 UTF-8 파일만 2 MiB까지 읽습니다. YAML 파싱·저장소 출처 검증·수동 연결은 아직 연결하지 않아 폴더 이름과 원문을 표시하고 출처는 미확인으로 둡니다. 현재 결과가 에이전트의 실제 로딩 여부를 뜻하지 않습니다.

첫 화면은 작업 구성입니다. 실제 설치된 스킬을 선택해 구성을 생성·편집·삭제하고, 구성 카드에서 포함된 스킬과 원문을 확인합니다. 구성 메타데이터는 앱별 UserDefaults에 저장하며 재실행 후 복원합니다. 목록에서 사라진 스킬 참조는 보존하고 현재 미발견 상태로 표시합니다. 구성 저장·선택은 스킬 파일을 바꾸지 않습니다. 실제 스킬 목록에서 에이전트·링크·검색 필터와 초기화, 폴더별 조회, 원문 상세의 경로 복사·Finder 열기를 제공합니다. 상단에는 새로고침과 설정을 글자와 함께 표시하며, 경로 관리와 화면 모드는 설정으로 모았습니다. 그룹·기록은 사이드바의 ‘준비 중’ 항목으로 표시합니다. 구성의 파일 적용·변경 검토·보관·복원·고정·복구, 메뉴 막대와 배포 검수는 다음 단계입니다. 따라서 아래 구현 순서의 1단계 전체가 완료된 상태는 아닙니다.

| 빌드 | Bundle ID | 표시 이름 | 서명 팀 |
| --- | --- | --- | --- |
| Debug | `forked.agentskillmanager.local.dev` | 스킬 작업대 Dev | 지정 없음 |
| Release | `forked.agentskillmanager.local` | 스킬 작업대 | 지정 없음 |

기본 빌드는 Apple 팀 없이 `Sign to Run Locally`로 ad-hoc 서명합니다. 서명 없이 컴파일만 확인할 때는 빌드 명령에 `CODE_SIGNING_ALLOWED=NO`를 추가합니다. 앱 파일 이름은 `AgentSkillManager Dev.app` / `AgentSkillManager.app`이며 화면의 표시 이름은 한국어입니다. 개인 Bundle ID와 Apple 팀은 Git에서 제외된 `Config/Local.xcconfig`에 설정합니다. Developer ID 서명·공증·배포는 아직 검증하지 않았습니다.

Debug·Release 빌드와 임시 폴더 코어 테스트 4개, 필터·경로 저장/복원·등록 해제·원본 보존의 앱 상태 검사를 통과했습니다. 작업 구성 생성·편집·검색·재실행 복원·삭제, 미발견 참조 보존, 손상 데이터 쓰기 차단과 스킬 파일 보존도 검사합니다. 초기 네이티브 검수에서 실제 설치 목록 조회, 960 × 800 pt 배치와 밝은·어두운 모드를 확인했습니다. 이후 사용자 요청으로 앱의 예시 보기·가상 데이터·개발용 예시 진입 인자를 제거하고 설정과 탐색을 재구성했습니다. 현재 실제 앱에서 에이전트 필터(Claude Code 75개), 폴더별 조회(Codex 62개), 검색 결과 없음·초기화, 설정 열기·폴더 선택 창과 원문 상세 열기/닫기를 확인했습니다. 이번 작업 구성 복구에서는 실제 창에서 생성·편집·원문 열기·재실행 복원·삭제를 확인했고 Release build 3을 설치했습니다. 검수용 구성은 삭제했으며 검수용 Debug 앱은 정상 종료·등록 해제 후 제거했습니다. 수동 경로 재실행 복원·원본 보존은 격리한 앱 상태 검사로 검증했습니다. VoiceOver·전체 키보드 탐색·macOS 26 실기기 검수는 남아 있습니다.

## 앱 아이콘

사용자가 선택한 B 시안의 Markdown 지침 묶음과 파란 명령 프롬프트 아이콘을 적용했습니다. Release는 `AppIcon`, 별도 Bundle ID의 Debug는 주황색 D 표시가 있는 `AppIcon-Dev`를 사용합니다. [원본과 생성 프롬프트](docs/design/icons/README.md) · [작은 크기 비교](docs/design/icons/size-preview.png). Xcode 자산은 `AgentSkillManager/Assets.xcassets`에 있으며 `project.yml`에서 빌드별 아이콘을 지정합니다. 두 빌드의 자산 컴파일과 서명을 확인했고, 현재 설치된 Release는 0.1.0의 build 4이며 B 아이콘을 사용합니다. [서비스 중심 아이콘 후보](docs/design/icons/service-candidates/README.md)는 비교 자료로 보존합니다. Debug·Release 자산 컴파일·서명과 설치본 아이콘을 확인했고, 설정을 보존하며 검수용 Debug 앱을 제거했습니다.

화면 시안은 브라우저에서 열 수 있는 검토 자료입니다. 웹 기술은 시안을 보여주는 용도로만 사용하며 제품 UI는 SwiftUI로 구현합니다. 시안 데이터는 예시이며 실제 설치 목록과 분리돼 있습니다.

출처 저장소별 분류를 설계에 추가했습니다. 출처는 가져온 곳, 그룹은 사용자가 만든 모음, 프로필은 정해진 관리 범위의 작업 목표입니다. 최종 후보 시안의 설치 목록에서 출처 필터·근거·설치 방식을 확인할 수 있습니다. 수동 연결·선택 항목의 그룹 생성은 첫 출시 설계에 포함하며 편집 화면은 아직 시안에 없습니다. 원격 설치·업데이트는 후속 범위입니다.

병렬 검토에서 확인한 고정·정상 복원·중단 롤백·기록 되돌리기·설정 수명 계약을 본 명세에 반영했습니다. 앱 전체 고정은 새 사용자 변경의 보관을 막고, 중단 롤백은 작업 전 상태와 물리적 검증을 따로 적용합니다. 첫 버전은 부분 적용과 관련 항목 자동 확장을 제공하지 않습니다.

본 명세와 시안 정합성 검사를 바탕으로 읽기 전용 코어와 네이티브 화면 구성을 시작했습니다. 사용자 파일 쓰기는 임시 폴더 쓰기 코어 테스트 통과 뒤 연결합니다. 현재 채택한 외형은 최종 후보의 중립색 팔레트이며, 현재 첫 화면은 작업 구성이며, 구성 메타데이터를 저장하고 스킬 파일은 읽기만 합니다.  초기 3단 시안은 비교 자료로 남깁니다.

브라우저를 열기 전에 [밝은 모드 화면 이미지](docs/design/preview-light.png)로 배치를 확인할 수도 있습니다.

## 확정한 범위

- 개인용 macOS 앱, 로컬 관리 중심.
- Codex와 Claude Code부터 지원.
- SwiftUI 네이티브 UI와 macOS 기본 컨트롤 사용.
- 스킬 조회와 검사, 작업별 구성, 변경 미리보기, 켜기·끄기, 복구가 중심 기능.
- 사용자 스킬의 변경과 시스템·플러그인·동기화 스킬의 조회를 구분.

| 최소 macOS 26 | 첫 네이티브 프로젝트의 deployment target. 실제 검증 환경은 macOS 27.0.1이며 macOS 26 실기기 검수는 남음 |
| 직접 배포하는 서명·공증 앱 | 사용자 스킬 폴더와 외부 볼륨을 관리하는 첫 버전의 배포 경로. App Store 배포는 별도 파일 권한 설계 필요 |
| 구조화된 로컬 JSON 저장 | 프로필과 변경 기록을 저장하는 단일 사용자 앱. 초기에는 데이터베이스가 필요하지 않음 |
| 프로필 적용 때마다 미리보기 | 변경 범위와 공유 항목을 눈으로 확인한 뒤 실제 파일 변경 |
| 기본 검사부터 제공 | AI 리뷰는 별도 단계. 실제 효과가 검증되지 않은 토큰 절감 수치는 표시하지 않음 |

첫 버전의 동작 계약은 메인 창 하나와 설정 창, 앱 전체 고정, 조회 범위와 관리 범위 분리입니다. 그룹·프로필·고정 편집은 스킬 파일을 바꾸지 않습니다. 실행·복구 중에는 발견 루트·보관 위치·고정·그룹·프로필·관리 범위 편집을 막고 조회·즐겨찾기·외형 변경은 허용합니다. 보관 위치는 실제 원자료이며 자동 정리하지 않습니다.

## 구현 순서와 완료 조건

| 단계 | 구현할 결과 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| 1 | 읽기 전용 발견과 라이브러리·출처 분류 | 두 에이전트의 사용자·프로젝트 스킬, 별도 복사본, 동일 원본 링크, 확인된 출처·수동 연결·미확인을 구별 |
| 2 | 임시 폴더의 변경 계획과 단일 항목 전환 | 충돌·외부 변경 시 파일 보존, 상대 링크 복구, 보관·복원·롤백 중단 경계와 수동 해결 검증 통과 후 사용자 쓰기 연결 |
| 3 | 그룹과 프로필 | 선택한 출처별 설치 항목으로 그룹 구성, 신규 항목 자동 편입 0건, 지정한 관리 범위만 변경, 전역 고정 보호, 겹치는 그룹 중복 처리 방지, 차단 시 전체 적용 불가 |
| 4 | 메뉴 막대와 기본 검사 | 메인 창과 동일한 계획·실행 경로 사용, 오프라인 검사 근거 표시 |
| 5 | 배포 검수 | VoiceOver·키보드·테마·외부 볼륨·실제 에이전트별 재발견 검증 |

본문 편집은 2단계에서 외부 편집기로 열기부터 제공하고, 앱 안의 편집은 충돌 감지와 파일 보존 조건을 만족한 뒤 추가합니다. AI 리뷰·자동 분류·팀 동기화·원격 마켓플레이스는 후속 범위입니다.

제품명과 장기 방향은 위의 [제품 방향](#제품-방향)을 따릅니다. 아래 구현 순서는 현재 스킬 관리 기능의 단계이며 전체 플러그인 관리 로드맵의 완료 조건은 아닙니다. 앱 아이콘은 서비스 중심 시안 B(스킬 지침 묶음)로 확정했습니다.

## 검토 자료 확인

```sh
node scripts/check-design.mjs
open docs/design/preview.html
```

첫 명령은 본 명세에 대응하는 시안의 계산·차단·복구 분류, 토큰 연결과 문서 링크를 검사합니다. 통과는 해당 시안 사례의 정합성 근거이며 실제 macOS 파일 변경 안전성을 뜻하지 않습니다. 실제 보관·복원·롤백, 강제 종료, 외부 변경·볼륨 조건과 SwiftUI 접근성·렌더링은 구현 뒤 별도로 검증해야 합니다.

2026년 10월 1일 Chrome DevTools로 시안의 프로필 적용, 오래된 계획 차단과 재확인, 복구 충돌 표현을 확인했습니다. 밝은·어두운 모드를 시각적으로 확인했고, 960 px 너비에서 가로 넘침 없이 사이드바 접기와 열기 행동이 제공됩니다. JavaScript 콘솔 오류는 없었습니다. 이는 브라우저 시안 검수이며 네이티브 앱 검수는 아닙니다.
