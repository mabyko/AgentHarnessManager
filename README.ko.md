# Agent Harness Manager

[English](README.md)

에이전트 스킬과 설치 위치를 살펴보고, 그룹으로 정리하며, 검토한 파일 변경을 적용하는 macOS 네이티브 앱입니다. SwiftUI로 만들며 Codex·Claude Code·Grok Build·Antigravity·OpenCode·Pi·Devin CLI·Cursor를 지원합니다.

**현재는 초기 개발 단계입니다.** 사이드바·목록·상세의 3열 화면을 사용하며 시각 스타일은 자체 스타일을 유지합니다. AI 검토·자동 그룹화·플러그인 설치·범용 MCP/훅 관리와 프로젝트 지침 편집은 아직 구현하지 않았습니다. 앱 화면은 한국어로 제공합니다.

## 현재 지원하는 기능

- 등록한 스킬 폴더를 보기 메뉴와 통합 필터 팝오버(에이전트·그룹·설치 위치·출처·링크)로 탐색. 적용 조건과 결과 수를 목록 위에 표시
- 논리적 스킬과 설치 위치 분리: 발견한 실제 원본과 그 원본을 가리키는 링크는 함께 표시하고, 이름만 같은 독립 복사본은 별도로 유지. ‘다른 버전’은 읽을 수 있는 동명 스킬의 `SKILL.md` 해시를 비교하며 전체 리소스 폴더를 비교하지 않음
- 설치 위치·출처·원문 확인과 즐겨찾기 저장. 설치 카드는 에이전트와 상태를 먼저 표시하고 경로·출처와 원문은 펼쳐서 확인
- **설치…**에서 공개 GitHub 저장소 URL 또는 로컬 `SKILL.md` 폴더를 입력해 기본 스킬 경로에 복사 설치. GitHub는 저장소에서 스킬을 선택하고 조회 당시 파일 해시를 검증하며, 적용 후 출처를 연결. 원본은 유지하며 설치 경로 검토·명시적 적용·충돌 차단·내용 재검증 제공. 일반 파일·폴더만 지원하고 심볼릭 링크·특수 파일은 거절
- **설정 → 일반 → 스킬 설치**에서 **앱 직접 설치**(기본) 또는 **skills CLI** 선택. CLI도 GitHub·로컬 입력을 지원하며 사용자 전역으로 설치할 에이전트 하나와 실제 명령을 검토. 기존 skills CLI 1.7.4 이상의 1.x 버전이 필요하며 실행 경로·기존 npx/bunx 캐시에서 감지하거나 실행 파일을 직접 선택. CLI 자동 다운로드나 설치 방식 자동 전환은 하지 않음
- 상세의 **설치 제거…** 또는 위치별 제거로 켜진/꺼진 설치를 라이브러리에서 제거. 복구용 파일과 기록은 보관하며 **활동 이력 → 변경**에서 이전 상태로 되돌릴 수 있음. 공유 원본·제공자 캐시·추가/중첩 경로 보호는 유지. 영구 삭제·GitHub 비공개 저장소 인증은 미지원. 비공개 저장소는 내려받은 로컬 폴더로 설치
- 그룹 생성·편집·삭제. 기존 작업 구성은 한 번만 그룹으로 가져오며 원래 메모와 누락 참조는 이전 작업 구성 화면에 보존
- 여러 그룹 함께 켜기 또는 다른 그룹 끄기. 다른 활성 그룹과 겹치는 스킬은 유지하고 그룹 밖의 스킬은 변경하지 않음
- 변경 검토 후 기본 발견 경로 10곳 바로 아래의 독립 폴더·정상적인 단일 설치 링크 켜기·끄기. 공유 원본은 유지하고 중첩/사용자 지정 경로·보호된 제공자 캐시는 읽기 전용으로 보호. 깨진 링크·다단계 링크·미등록 원본은 차단하고 적용 전 새 탐색과 식별·내용 검증 수행
- 변경 기록 저장, 덮어쓰기 차단과 중단된 변경 재개. 복구 전까지 다른 파일 변경 차단
- 완료·중단된 변경 이력과 설치 경로 검색, 역방향 계획 검토 후 완료 작업 되돌리기. 원래 작업과 실행 기록을 보존하고 재실행·복구 후 그룹 선택을 기록에 맞춰 조정
- 문서 읽기·제한된 메타데이터·경로의 로컬 검사와 최근 50회 이력 저장. 검사 근거·해시·현재 상태와의 일치 여부 확인
- 설정에서 경로와 시스템·밝은·어두운 화면 관리. 경로 등록 해제는 파일을 삭제하지 않음
- 스킬의 에이전트 필터에는 설치가 감지된 에이전트만 표시하고 설정에서는 8개 전체와 설치 상태 표시. CLI·지원 앱 파일만 확인하며 에이전트 실행이나 인증 정보 조회는 하지 않음. 직접 등록한 다른 에이전트는 계속 표시하고 미설치 에이전트의 스킬 데이터도 유지
- 사용자 정의 사이드바 버튼의 키보드 탐색과 대상별 접근성 이름 제공. 에이전트 이름·연결 상태를 함께 읽고 연결 작업·경로를 구별
- Codex·Claude Code·Grok Build·Antigravity·OpenCode·Pi의 사용자 전역 지침 파일 조회·편집·생성. 저장과 로컬 백업 복원 전 원문 비교를 검토하며 외부 변경 시 오래된 초안 적용을 차단. 지원하는 공유 파일 링크는 유지하고 원본을 편집. Cursor·Devin CLI는 이 파일 편집 기능에서만 미지원으로 표시
- 앱에 포함한 CLI·stdio MCP로 Codex·Claude Code·Grok Build·Antigravity·OpenCode·Pi·Devin CLI·Cursor와 연동. 목록·원문·로컬 검사 조회, 켜기·끄기 계획과 앱 승인 요청 제공. 연결 설치·제거 전에 명령 또는 MCP 등록과 설정 경로를 확인하고 기존 설정을 백업. 공유 호환 경로는 설치를 중복 생성하지 않고 영향받는 에이전트를 표시

공유 원본이 있는 스킬의 그룹·전체 전환은 설치 링크만 바꿉니다. 원본 폴더는 켜진 상태로 유지하고 라이브러리의 실제 파일 상태에 포함하므로 모든 설치 링크가 꺼져도 원본은 켜짐으로 집계됩니다. 에이전트별 링크는 따로 전환할 수 있습니다.

그룹의 선택 상태와 설치 위치의 실제 켜짐 상태는 별개입니다. 그룹 편집과 즐겨찾기는 메타데이터만 바꿉니다. 파일 전환은 별도의 변경 검토와 적용을 거칩니다. 발견·켜짐 상태는 에이전트가 현재 대화에서 읽었다는 뜻이 아닙니다.

## 빌드와 실행

macOS 26 이상, Swift 6.2 이상을 포함한 Xcode 26 이상이 필요합니다. 전체 Xcode 설치를 활성 개발자 경로로 선택해야 합니다. 외부 Swift 패키지 의존성은 없습니다. 디자인 검사에는 Node.js 22 이상, CLI·MCP 검사에는 Python 3이 필요합니다. 빌드된 앱에는 관리 실행 파일이 포함되므로 사용자는 Swift SDK를 설치할 필요가 없습니다.

저장소에 포함된 프로젝트를 열고 `AgentHarnessManager` scheme을 선택해 실행합니다.

```sh
open AgentHarnessManager.xcodeproj
```

저장소 루트에서 로컬 Release 앱을 빌드하고 실행하려면:

```sh
xcodebuild -project AgentHarnessManager.xcodeproj \
  -scheme AgentHarnessManager -configuration Release \
  -derivedDataPath build build
open "build/Build/Products/Release/Agent Harness Manager.app"
```

기본 빌드는 ad-hoc 서명을 사용하므로 Apple 팀 설정이 필요하지 않습니다. Debug 빌드는 별도의 `Agent Harness Manager Dev.app`과 설정 저장 영역을 사용합니다. 위 명령은 로컬 빌드용이며 Developer ID 서명과 공증 배포는 아직 검증하지 않았습니다.

생성된 Xcode 프로젝트를 저장소에 포함합니다. [project.yml](project.yml)을 변경해 프로젝트를 다시 생성할 때만 XcodeGen이 필요합니다.

```sh
xcodegen generate --spec project.yml
```

개인 서명 설정은 Git에서 제외하는 `Config/Local.xcconfig`에 작성합니다. 설정 방법과 검사는 [CONTRIBUTING.md](CONTRIBUTING.md)를 참고하세요.

## 사용 방법

1. 설정(`⌘,`) → **스킬 경로**에서 에이전트를 선택하고 기본·공유 경로를 확인하거나 조회할 폴더를 추가합니다. 다른 에이전트의 경로는 선택 메뉴의 ‘다른 에이전트’에서 관리합니다.
2. 왼쪽에서 **스킬 라이브러리**를 열고 목록 위의 보기 메뉴와 **필터** 버튼으로 범위를 좁힙니다. 에이전트·그룹·설치 위치·출처·링크 조건을 한 팝오버에서 함께 적용하거나 초기화할 수 있습니다. **설치…**에서 GitHub 주소를 불러와 스킬을 고르거나 로컬 폴더를 선택하고, 설치 위치를 정한 뒤 설치 경로를 검토하고 적용합니다. 상세의 **설치 제거…**에서 설치 제거를 검토할 수 있습니다. 스킬을 선택하면 오른쪽에서 설치 위치·그룹·출처·원문을 확인합니다. 외부 변경 뒤에는 `⌘R`로 새로고침합니다.
3. 스킬 라이브러리의 **그룹** 화면에서 ‘새 그룹’으로 스킬을 묶고 멤버를 편집하거나 켜기·끄기를 요청합니다. 다른 그룹을 함께 유지할지 선택할 수 있습니다.
4. 지원되는 파일 전환을 요청하면 모든 출발·도착 위치를 검토하고 적용합니다. 중단되면 표시된 충돌을 해결한 뒤 ‘복구 재시도’로 기록된 작업을 마칩니다.
5. **활동 이력 → 변경**에서 이동 경로를 확인하거나 ‘되돌리기 검토…’로 역방향 계획을 확인한 뒤 적용합니다.
6. 새로고침 후 도구 막대의 ‘검사’를 누르면 현재 로컬 검사 결과를 저장합니다. **활동 이력 → 검사 이력**에서 당시의 근거를 확인합니다.
7. **전역 지침**에서 목록 위의 에이전트 메뉴와 파일을 선택하고 Markdown을 편집합니다. 없는 후보는 **초안 작성**으로 시작해 내용을 입력하고 **파일 만들기 검토… → 파일 만들기**를 거쳐 생성합니다. 기존 파일은 **변경 검토…** (`⌘S`) 후 저장하세요. **백업 복원**과 조건에 맞는 새 파일의 **만들기 되돌리기…**도 검토 후 적용하며 기존 파일을 임의로 삭제하는 기능은 없습니다. 화면 이동·새로고침 후에도 초안을 보존하고 종료 시 저장하지 않은 초안을 알립니다. 자세한 내용은 [전역 지침 파일](docs/global-instructions.md)을 참고하세요.

## 에이전트 CLI·MCP 연동

설정(`⌘,`) → **에이전트 연동 · CLI / MCP**에서 사용할 에이전트의 **연결 설치…**를 누릅니다. 설정 경로와 명령 또는 MCP 등록을 확인하고 적용합니다. Codex·Claude Code·Grok Build는 설치된 CLI의 설정 명령을 사용합니다. Antigravity·OpenCode·Pi·Devin CLI·Cursor는 검토한 JSON/JSONC 항목을 수정하므로 등록 저장만 할 때는 해당 CLI가 필요하지 않습니다. **등록 상태 확인**은 이 다섯 에이전트나 MCP 서버를 실행하지 않고 저장된 항목을 확인합니다. 등록만으로 에이전트 설치나 도구 로딩을 확인한 것은 아니므로 새 세션에서 실제 사용을 확인하세요. 인증은 각 에이전트가 처리하며 이 앱은 별도 모델 계정 로그인이나 키체인 접근을 하지 않습니다.

에이전트에 목록·문서 조회나 설치 항목의 켜기·끄기 요청을 맡긴 뒤, 앱의 **활동 이력 → 요청** → **현재 상태로 검토…**에서 계획을 확인하고 적용합니다. 요청은 24시간 뒤 만료되며 파일·포함 리소스·설정·관련 이력이 바뀌면 차단합니다. 요청 전송만으로 파일이 바뀌지 않습니다. 그룹은 조회만 제공하고 에이전트의 그룹 편집·선택 변경은 후속 범위입니다.

CLI는 앱의 `Contents/Helpers/ahm`에 포함하며 설정에서 경로를 복사할 수 있습니다. 자세한 명령·설정 범위·백업·제한은 [CLI·MCP 사용법](docs/agent-integration.md)을 참고하세요. 앱 자체를 MCP 서버로 연결하는 기능이며 다른 MCP 서버들을 관리하는 기능은 아닙니다.

설치 감지와 MCP 등록 상태는 별개입니다. **설치 상태 확인**은 에이전트 명령을 실행하지 않고 로컬 파일을 다시 확인하며, **등록 상태 확인**은 기존 설정 확인 절차로 MCP 등록을 확인합니다. 설치가 감지되지 않으면 연결 설치 버튼을 비활성화합니다. Codex·Claude Code·Grok Build의 연결 설정에는 데스크톱 앱이 있더라도 감지된 CLI가 필요합니다. JSON 기반 등록은 에이전트가 미설치 상태여도 기존 등록 제거를 검토할 수 있습니다.

설치 감지는 절대 `PATH`, 일반 사용자 CLI 폴더, Homebrew·시스템 실행 경로를 확인합니다. Codex·Antigravity·OpenCode·Cursor 앱은 `/Applications`와 `~/Applications`의 실행 파일이 있는 번들로 확인합니다. 사용자 지정 위치·이름 변경 앱·사용할 수 없는 버전 관리자 명령은 놓칠 수 있습니다. 설치 감지와 관계없이 설정에서 스킬 경로를 확인할 수 있으며, 감지는 로그인·버전 호환성·실제 도구 사용을 보장하지 않습니다.

## 로컬 데이터와 파일 접근

그룹·즐겨찾기·로컬 검사 이력·이전 작업 구성·수동 출처·추가 경로·화면 설정은 로컬 `UserDefaults`에 저장합니다. 그룹으로 가져올 때 원래 작업 구성 데이터는 그대로 남깁니다. 손상된 그룹·검사·출처 데이터도 보존하고 해당 저장을 잠급니다. 로컬 스킬 관리는 계정·네트워크 없이 동작하고 스킬 스크립트를 실행하지 않습니다. GitHub 설치를 명시적으로 선택할 때만 공개 GitHub API를 조회하며 쿠키·저장된 인증 정보를 사용하지 않습니다. 조회 한도 오류 시 부분 설치를 남기지 않고 로컬 폴더 설치를 안내합니다. 앱은 모델 제공자의 인증 정보를 저장하거나 키체인에 접근하지 않습니다. 사용 정보 수집은 없습니다.

전역 지침 저장 전 원본은 스킬 변경 기록과 별도로 `~/Library/Application Support/<bundle-id>/InstructionBackups/`에 보관합니다. 지침 원문이 포함된 비공개 로컬 백업이므로 개인 백업에도 함께 보관하세요. 탐색·검토만으로 지침 파일을 만들지 않으며, CLI·MCP에는 지침 편집이나 백업을 노출하지 않습니다.

파일 변경은 `~/Library/Application Support/<bundle-id>/Library/library-journal.json`에 기록하며 배타 잠금과 원자적·디스크 동기화 저장을 사용합니다. 끈 폴더나 설치 링크는 발견 경로의 고유한 `.ahm-disabled-<UUID>` 형제 위치(예: `~/.agents/skills` 밖의 `~/.agents` 아래)에 같은 볼륨으로 보관하고 기록을 통해 읽습니다. 보관·복원 뒤에도 원래 설치 식별자를 유지합니다. 스킬을 끈 상태에서 앱을 제거하거나 백업할 때는 기록과 보관 폴더를 함께 유지해야 합니다. 중단 복구는 기록된 계획을 재개하며 최근 완료 기록 100회를 보존합니다. 되돌리기는 새 역방향 작업으로 기록하고 같은 설치 위치의 후속 변경·내용 편집·경로 충돌·새 공유 참조를 차단합니다. 폴더 지문이 없는 이전 기록은 조회만 제공합니다. 되돌리기 실행을 다시 되돌리기와 강제 복구는 제공하지 않습니다.

폴더 지문은 포함 파일의 바이트·이름·권한 모드·폴더 구조와 내부 링크 문자를 확인하며 그 내부 링크 대상은 열지 않습니다. 설치 링크 전환은 등록한 원본의 폴더 식별 정보와 지문도 확인하고 원본 자체는 이동·수정하지 않습니다. 일반 파일 내용 합계 64 MiB·10,000개 항목·폴더 32단계 한도를 적용하고 읽을 수 없는 항목이나 특수 파일이 있으면 변경을 막습니다. 그룹 선택 의도는 파일 이동과 함께 기록하고 완료·복구 후 설정에 반영합니다. 되돌리기는 그룹 정의·즐겨찾기·검사 이력을 변경하지 않습니다.

설치 링크는 문자와 inode를 그대로 보관합니다. 상대 링크 원문은 원래 설치 위치를 기준으로 읽으며 보관 위치의 링크를 따라가지 않습니다. 보관 중인 상대 링크를 Finder에서 직접 열면 다른 곳을 가리킬 수 있으므로 표시한 원본 경로나 앱의 원문 보기를 사용하세요. 복원·되돌리기도 링크 식별·문자 변경, 원본 교체, 목적지 충돌, 설치/보관 링크를 거치는 새 참조를 차단합니다. 첫 링크 작업에서 저널을 버전 2로, 설치·제거 작업에서 버전 3으로 올리고 기존 기록은 유지합니다. 제거한 항목은 보관 파일과 저널에 남고 라이브러리에서는 숨깁니다. 설치 검토 취소 시 준비 복사본은 제거하지만, 저널 저장 전 앱이 종료되면 루트 옆에 참조되지 않은 `.ahm-disabled-<UUID>` 준비 폴더가 남을 수 있습니다. 꺼진 항목 제거는 파일을 다시 이동하지 않습니다. 이전 앱은 새 메타데이터를 잃지 않도록 지원하지 않는 저널 버전의 쓰기를 거절합니다.

등록한 경로 안에서만 탐색합니다. 원문은 2 MiB 이하의 일반 UTF-8 파일만 읽고, 등록 경로 밖을 가리키는 링크는 차단합니다. 경로별 탐색 깊이는 8, 후보 수는 10,000개로 제한하며 불완전한 결과를 표시합니다. 이 수치는 앱의 제한이며 에이전트 명세가 아닙니다.

출처 자동 분류는 `~/.agents/.skill-lock.json`에 있는 버전 3 [Vercel Skills 설치 기록](https://github.com/vercel-labs/skills/blob/main/src/skill-lock.ts)을 읽습니다. 지원하는 GitHub/Git 기록을 `~/.agents/skills`의 해당 실제 폴더와 그 폴더를 가리키는 등록된 항목에만 연결합니다. 다른 위치의 동명 복사본은 출처 미확인으로 남깁니다. 이 메타데이터도 링크·특수 파일을 거부하고 2 MiB 이하만 읽습니다. `XDG_STATE_HOME`의 별도 기록, 프로젝트 기록, 플러그인 기록은 아직 지원하지 않습니다.

“설치 기록”은 설치 당시 기록, “직접 연결”은 사용자가 앱에서 지정한 출처입니다. 현재 파일과 원격 저장소의 일치 여부는 확인하지 않습니다. 설치 개수는 복사본과 링크를 각각 세며, 스킬 개수는 함께 표시한 공유 원본을 구분해 셉니다. 어느 쪽도 원격 저장소의 스킬 총수가 아닙니다. 일부 위치만 켜진 스킬은 켜짐·꺼짐 필터에 모두 나타날 수 있습니다. 수동 연결은 발견한 설치 항목의 식별자에 저장하므로 폴더를 교체하면 자동 승계하지 않습니다. 수동 연결을 해제하면 설치 기록이 있는 항목은 그 출처로 돌아갑니다. 수동 출처는 보관·복원 후에도 유지합니다. 보관 중에는 자동 설치 기록 출처를 확인하지 못할 수 있으며 복원 후 다시 검증합니다. 출처 선택·편집은 스킬 파일을 바꾸지 않습니다.

이름 변경 전의 설정을 유지하기 위해 기존 Bundle ID인 `forked.agentskillmanager.local`과 `.dev`를 보존합니다. [Config/Base.xcconfig](Config/Base.xcconfig)에 정의되어 있습니다.

CLI 설치는 검토한 GitHub 커밋·하위 폴더 또는 로컬 폴더를 기존 실행 파일에 전달합니다. CLI가 자체 네트워크 접근·설치 파일·복사/링크 방식·설치 기록을 관리하며, 에이전트 하나를 지정하면 복사로 설치할 수 있습니다. 자식 프로세스의 텔레메트리는 끕니다. 기존 설치 경로·지원하지 않는 설치 기록·검토 후 변경된 원본은 실행을 차단합니다. CLI 설치에는 앱 변경 이력의 자동 되돌리기가 없고 실패 시 일부 변경이 남을 수 있습니다. 설치 제거는 계속 앱의 복구 가능한 보관 방식을 사용하며 `skills remove` 실행이나 CLI 설치 기록 수정은 하지 않습니다.

## 앞으로의 계획

- 검증한 에이전트별 발견 규칙, 출처 기록 형식과 플러그인 소속 지원 확대
- 기본 경로의 폴더·단일 설치 링크 외의 파일 전환, 복구 도구 확대, AI 검토·자동 그룹화
- 검증한 에이전트 공식 경로로 플러그인 설치·업데이트 지원, 이후 지원 가능한 MCP 서버·훅·프로젝트 지침으로 확장
- 접근성·배포 검수

플러그인은 배포 패키지, 저장소는 출처, 작업 구성은 사용자의 선택입니다. 단독 스킬은 그대로 다룹니다. 디자인 시안에는 미래 기능이 포함되어 있으며 현재 앱의 지원 범위를 뜻하지 않습니다.
