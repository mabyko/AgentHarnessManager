# 최종 후보: 차분한 작업대

2026-10-01. 사용자가 이 시안을 기준으로 macOS·SwiftUI 프로젝트 구성을 시작하도록 승인했다. 작업 구성 중심 구조와 무채색 바탕·절제된 파란 강조색을 네이티브 구현 기준으로 채택한다. 2026-10-02 제품명은 **Agent Plugin Manager**로 확정했다. 앱 표시 이름·창 제목·Xcode 프로젝트와 시안의 제품명을 함께 변경했다. 기존 설정을 유지하도록 Bundle ID는 보존한다. [눌러보는 시안](final-preview.html)은 브라우저에서 열 수 있고 예시 데이터만 메모리에서 바뀐다. 네이티브 구현 범위와 실행 방법은 [README](../../README.md#build-and-run)에 기록했다.

## 스타일과 정보 구조

밝은 모드는 흰색·회색, 어두운 모드는 차콜·회색의 무채색 표면을 사용한다. 선택·포커스·주요 행동에만 파란색을 소량 사용하고, 녹색은 상태 표시, 황색은 주의, 적색은 오류로 분리한다. 선택한 카드·행·사이드바의 넓은 바탕은 중립색이며 일반 아이콘과 변경 필요 수치는 보조 글자색을 사용한다. 시스템 서체와 가는 선 아이콘, 낮은 그림자, 작은 모서리로 정보의 계층을 만든다. 현재 색상 기준은 `final-preview.html`의 `design-tokens`이며 앱의 `WorkbenchTheme`에 필요한 역할을 반영했다. `tokens.json`은 초기 시안 검증용 값으로 유지한다. 네이티브의 기본 컨트롤·창·메뉴·사이드바 재료는 시스템 표현을 따른다.

이전 녹색 팔레트는 배경·텍스트·선택·주요 행동·상태에 같은 색 계열을 넓게 사용해 녹색 기운이 강해졌다. 사용자 피드백을 반영해 색상 역할과 사용 면적을 재조정했다. 앞선 병렬 검토의 사용성·정합성 확인이 팔레트의 최적성이나 사용자 선호까지 입증한 것은 아니다. 현재 파란 강조 역시 추천 기본값이며 브랜드 확정은 아니다.

| 화면 | 배치와 판단 |
| --- | --- |
| 작업 구성 | 프로필을 고르고 아래에서 관리 대상·위치·목표를 확인한다. 구성 선택은 적용과 분리하고 실제 파일과의 차이를 표시한다. |
| 설치 목록 | 이름·에이전트·위치·상태를 넓은 목록에서 비교한다. 항목을 선택하면 상세 창을 열고 본문·공유 원본·고정·즐겨찾기를 확인한다. |
| 출처 분류 | 설치 목록의 출처 필터로 저장소별 항목을 좁힌다. 행에는 출처 이름·근거 표시를, 상세에는 저장소 내부 위치·설치 방식·버전의 확인 여부를 표시한다. 관리 주체와 출처는 별개다. |
| 변경 검토 | 복원·보관 수, 전역 영향, 각 항목의 출발·도착, 고정과 범위 밖 유지, 차단 근거를 함께 보여준다. 부분 적용은 제공하지 않는다. |
| 확인 필요·그룹 | 목록에서 항목을 고르고 근거 또는 구성원을 상세 창에서 확인한다. 그룹은 분류이며 파일 전환 스위치가 아니다. |
| 기록·복구 | 적용한 예시 변경과 되돌리기를 기록한다. 충돌 예시는 원래 위치와 보관 위치를 나란히 보여주고 보존·차단을 설명한다. |

프로필 행과 목록의 접근성 이름에는 전체 설치 위치를 포함한다. 공유 원본·고정·읽기 전용을 색만으로 구별하지 않는다. 검색·조회 필터는 프로필의 지정 관리 범위를 바꾸지 않는다. 적용·상세 창 닫기 뒤 키보드 포커스를 적절한 컨트롤에 돌려준다.

2026-10-01의 한 차례 병렬 검토에서 제품 UX·시각/접근성·계약 정합성을 세 에이전트가 나눠 검토했다. 스타일과 작업 구성 중심 구조는 유지하고 탐색 맥락과 변경 대상 식별을 개선했다. 작업 구성 안의 항목 확인은 현재 구성을 유지하고, 변경 행은 `발견됨 → 보관` 또는 `보관됨 → 복원`으로 표시한다. 유지 행은 중립색으로 둔다. 설치 목록은 `표시 항목 / 출처 범위 전체 항목`을 구별하고 설치 경로로도 검색한다. 좁은 창에서 위치 열을 숨기면 에이전트·경로를 이름 아래에 표시한다.

명시적인 화면 이동은 검색을 초기화하고 상세 창을 닫지만, 재검사·외부 관찰은 검색을 보존한다. 작업 구성·변경 기록에서는 에이전트 조회 필터를 비활성화하고 이유를 안내한다. 상세 창을 닫으면 해당 항목으로 포커스를 돌려주고, 모달 안에서는 배경 검색 단축키를 가로채지 않는다. 다이얼로그는 본문만 스크롤하고 하단 행동은 유지한다. 판단과 남은 검수 한계는 [병렬 검토 기록](../design-review.md#최종-후보의-한-차례-병렬-검토)에 기록했다.

이번 시안은 사용자 전역 위치와 제공자 카탈로그의 예시만 담았다. 프로젝트 등록·프로필 편집·그룹 편집·설정·실행 중단·수동 복구의 모든 화면을 구현한 결과가 아니다. 특히 복구 충돌 창은 설명용 예시이며 실제 중단 복구나 전체 쓰기 잠금을 검증하지 않는다. 기능 계약은 [아키텍처](../architecture.md)와 [사용자 시나리오](../product-scenarios.md)를 따른다.

출처 분류는 `mattpocock/skills`에 세 예시 설치 항목을 수동 연결한 시나리오다. 실제 Mac의 설치 출처를 검증한 결과가 아니다. `mabyko/mabyko-kit`은 등록한 출처이지만 현재 예시에서 연결된 설치 항목은 0개이며, 비공개 저장소의 내용이나 원격 총수를 가정하지 않는다. 나머지는 출처 미확인으로 남긴다. 출처 필터는 설치 목록에만 적용하며 프로필 목표·관리 범위·파일 상태를 바꾸지 않는다.

첫 출시 설계에는 출처 수동 연결과 `선택한 설치 항목으로 그룹 만들기`를 포함한다. 그룹은 선택 ID의 스냅샷을 저장하며 출처에서 새 항목이 발견돼도 자동 편입되지 않는다. 출처 편집·다중 선택·그룹 생성·프로필 편집 화면은 이 시안에서 아직 구현하지 않았다. 원격 설치·업데이트는 후속 단계다.

## 네이티브 구성 시작

승인한 스타일을 SwiftUI로 옮겼다. 실제 설치 목록을 읽기 전용으로 확인한다. 초기 검수용으로 포함했던 예시 보기·가상 작업 구성·가상 변경 검토는 사용자 요청으로 앱에서 제거했다. 브라우저 시안은 별도의 설계 자료로 유지한다. Debug·Release 로컬 빌드, 탐색·원문 읽기의 임시 폴더 테스트 4개, 실제 창의 밝은·어두운 모드와 960 × 800 pt 배치를 확인했다. 수동 스킬 경로와 화면 모드는 설정 창으로 모았으며 추가 경로는 재실행 후 복원한다. 작업 구성 중심의 메인을 첫 화면으로 복구했다. 가상 카드 대신 실제 설치 항목을 선택해 생성·편집·저장·삭제하는 구성 카드와 구성별 스킬 목록을 제공한다. 구성 선택·저장으로 파일은 바뀌지 않는다. 미발견 참조는 보존한다. 별도 그룹 화면은 현재 작업 구성과 역할이 겹쳐 제공하지 않는다. 구성 편집의 ‘다른 구성에서 가져오기’로 기존 구성의 스킬을 한 번에 추가한다. 가져온 목록은 이후 원래 구성 편집·삭제로 바뀌지 않는 스냅샷이다. 변경 기록은 파일 변경 기능을 구현할 때 연결하며 사이드바에서는 숨긴다. 파일 적용·목표 state.json 통합·출처 편집·VoiceOver 전체 검수는 후속 단계다.

## 실행과 검토

```sh
open docs/design/final-preview.html
node scripts/check-design.mjs
```

시안은 이전 화면과 같은 `preview-model.js`·`preview-controller.js`를 사용한다. 검사는 후보의 프로필 적용·고정 차단·오래된 계획 차단·포커스 요청, 모달 열림·닫힘, 탐색 맥락 보존, 결과 수·설치 경로 검색과 양쪽 테마의 글자 대비를 포함한다. 메모리 DOM 검사만으로 실제 브라우저 포커스 복원을 입증하지 않으며 아래의 브라우저 확인과 구별한다. 실제 파일 이동과 SwiftUI·VoiceOver 검증은 포함하지 않는다.

Chrome DevTools에서 프로필의 예시 적용, 고정 항목 보관 차단, 외부 변경 후 실행 차단·재확인·적용, 적용 후 포커스 복원을 확인했다. 밝은·어두운 화면을 직접 확인했고 960 × 800 px에서 가로 넘침 없이 사이드바를 열고 닫을 수 있었다. 복구 충돌 예시는 두 위치와 보존 이유를 표시했다. 확인한 브라우저 세션에 JavaScript 콘솔 오류는 없었다.
