# Agent Harness Manager 사용자 시나리오와 제품 범위

사용자는 여러 에이전트에 설치한 스킬의 위치와 상태를 확인하고, 지금 할 작업에 필요한 구성을 선택하고 싶습니다. 앱은 파일 변경의 범위를 설명하고 되돌릴 수 있게 하며, 에이전트의 현재 대화 상태를 확인한 것처럼 표현하지 않습니다.

이 설계의 확정 범위는 개인용 로컬 macOS 앱과 Codex·Claude Code 지원입니다. 최소 macOS 26과 직접 배포는 제안이며, 기술 선택과 변경 계약은 [개발 아키텍처](architecture.md)에 있습니다.

## 후속 플러그인 관리의 사용자 흐름

2026-10-02 사용자는 제품명을 **Agent Harness Manager**로 확정했습니다. 아래는 후속 확장 방향이며 현재 구현은 다음 절의 읽기 전용 스킬 조회와 작업 구성 저장입니다.

1. 사용자가 플러그인을 찾고 포함된 스킬·MCP·훅 등과 출처, 지원 에이전트를 확인합니다. 저장소 이름만으로 플러그인 소속이나 호환을 추정하지 않습니다.
2. 지원이 검증된 에이전트에서 설치·업데이트할 패키지와 예상 영향을 확인합니다. 패키지 단위의 공식 관리 경로를 사용하며 내부 캐시 파일을 개별 이동하지 않습니다.
3. 설치 후 확인 가능한 파일·등록·활성·대화 반영 상태를 구분합니다. 관찰하지 못한 상태는 미확인으로 표시합니다.
4. 필요한 패키지와 단독 항목을 작업 구성에 연결합니다. 구성 저장과 실제 적용을 구분하며 항목별 지원 여부를 확인합니다.

라이브러리에서는 플러그인·스킬·MCP·훅·지침을 원래 이름으로 구별합니다. 패키지 포함 항목은 소속과 관리 주체를 표시하고 관리할 때 패키지로 이동하도록 안내합니다. 직접 등록한 스킬은 단독 항목으로 유지합니다. 모든 항목을 ‘플러그인’이나 ‘애드온’으로 다시 분류하지 않습니다. 후속 종류의 화면은 지원 기능을 구현한 뒤 연결하며 현재 앱에 동작하지 않는 탭을 먼저 추가하지 않습니다.

**인수 방향:** 같은 저장소의 단독 스킬과 플러그인 패키지를 구별하고, 지원하지 않는 에이전트에서는 이유를 표시합니다. 미지원과 미확인, 파일 발견과 실제 로딩을 구별합니다. 공통 지침과 실행 루프 관리의 차이를 설명하며 실행 루프 제어를 제공하지 않습니다. 추천·평점·공유는 후속 범위입니다.

## 현재 읽기 전용 앱의 흐름

첫 실행은 작업 구성을 엽니다. 초기에는 가상 카드를 만들지 않고 구성 생성과 실제 스킬 목록 탐색을 안내합니다. 이름·설명과 현재 설치 항목을 선택해 저장하면 구성 카드가 생깁니다. 구성 선택으로 포함된 스킬과 원문을 확인하며 편집·삭제와 재실행 복원을 제공합니다. 미발견 항목은 참조를 보존하고 명시적으로 제외할 수 있습니다. 저장은 구성 메타데이터만 바꾸며 파일 적용은 준비 중입니다. 스킬 목록의 상단은 검색·새로고침·설정, 목록 위는 에이전트·링크 필터와 초기화, 사이드바는 전체 목록·확인 필요·폴더별 조회입니다. 구성 편집의 ‘다른 구성에서 가져오기’로 기존 구성의 현재 스킬을 선택 목록에 추가하고 중복은 합칩니다. 목록에 없는 스킬이 있으면 전체 가져오기를 막고 이유를 표시합니다. 저장한 구성은 이후 원래 구성 편집·삭제로 바뀌지 않는 스냅샷입니다. 별도 그룹 화면은 현재 기능에서 작업 구성과 역할이 겹쳐 제공하지 않습니다. 아래 목표 계약의 그룹 연결·관리 범위 검증·파일 적용은 후속 범위입니다. 변경 기록은 실제 파일 변경 기능과 함께 연결하며 준비 중인 화면은 현재 사이드바에 표시하지 않습니다. 검색 결과가 없으면 필터 초기화를, 스킬이 없으면 설정에서 경로 확인을 안내합니다.

설정은 Codex·Claude Code의 스킬 폴더 상태와 추가 경로, 화면 모드를 관리합니다. 에이전트별로 기본·추가 경로와 추가 버튼을 함께 표시합니다. 기본 경로는 고정이며 추가 경로만 수정·삭제할 수 있습니다. 다른 에이전트는 이름을 입력해 스킬 폴더를 등록합니다. 수동 경로는 재실행 후 유지되며 등록 해제는 실제 파일을 삭제하지 않습니다. 다른 에이전트는 SKILL.md 조회만 지원합니다. 폴더 발견을 에이전트 설치 또는 실제 로딩 확인으로 표시하지 않습니다. SKILL.md 상세에는 경로 복사와 Finder 열기를 제공합니다. 이 흐름은 현재 구현 범위이며 아래 내용은 파일 변경 기능까지 포함한 목표 계약입니다.

## 사용자와 사용 상황

| 사용자 | 상황 | 필요한 결과 |
| --- | --- | --- |
| 여러 에이전트를 쓰는 개발자 | 같은 스킬을 공용 폴더와 에이전트별 폴더에 설치 | 원본 공유와 별도 복사본 구분, 변경 영향 확인 |
| 작업 종류를 자주 바꾸는 사용자 | 앱 개발에서 문서 작성으로 전환 | 프로필 한 번 선택으로 관련 항목만 전환 |
| 스킬을 직접 작성하는 사용자 | 설명·지침·참조를 수정 | 검사 근거와 설치 위치 확인, 변경 후 재검사 |

앱 설치만으로 기존 구성을 바꾸지 않습니다. 첫 실행에서 찾은 결과는 조회만 하며, 사용자가 변경할 때 최초의 쓰기 작업을 시작합니다.

## 화면 구조

첫 버전은 메인 창 하나와 설정 창을 제공합니다. 아래 3단 구조와 메뉴 배치는 기존 참고 시안의 구성입니다. 새 UI에서는 열 수·탐색 방식·요약 타일을 바꿀 수 있습니다. 변경의 단위는 설치 항목이며 같은 이름이라는 이유로 서로 다른 설치 항목을 합쳐 변경하지 않습니다. 스킬별로 묶어 표시하더라도 실제 설치 대상을 구별해 선택할 수 있어야 합니다.

| 위치 | 내용 |
| --- | --- |
| 상단 도구 막대 | 조회 범위, 검색, 다시 검사, 변경 진행 상태 |
| 사이드바 요약 | 전체, 발견 위치에 있음, 보관됨, 확인 필요, 읽기 전용, 즐겨찾기 |
| 사이드바 탐색 | 라이브러리, 그룹, 프로필, 검사 결과, 변경 기록, 등록 프로젝트 |
| 목록 | 이름, 설명, 에이전트·위치, 출처 저장소 필터, 파일 상태, 관리 가능 여부, 검사 결과 수 |
| 상세 | 상태와 가능한 행동, 설명, 설치 위치·공유 관계, 출처 근거·설치 방식, 검사 결과, 지침 본문 |
| 변경 미리보기 | 켜질 항목, 꺼질 항목, 유지 항목, 공유 영향, 차단 사유 |
| 설정 | 발견 위치, 보관 위치, 메뉴 막대, 외형, 검사 제한 |

메뉴 막대는 프로필, 고정 항목 상태, 메인 창 열기를 제공합니다. 프로필을 클릭하면 메인 창의 변경 미리보기를 엽니다. 첫 버전에서는 미리보기를 생략하는 별도 빠른 실행 경로를 만들지 않습니다.

설치 항목 수와 화면의 묶음 수는 구분해 표시합니다. 같은 에이전트의 같은 이름 항목도 사용자 위치·프로젝트명·짧은 경로로 구별하고, 접근성 이름에는 전체 설치 위치를 포함합니다.

카탈로그 존재와 플러그인 활성 여부도 구별합니다. 파일을 읽을 수 있다는 사실만으로 에이전트가 사용할 수 있다고 추정하지 않습니다.

여러 프로필이 동시에 구성 일치할 수 있습니다. 관리 범위가 다른 프로필로 전환해도 이전 프로필의 범위 밖 항목을 자동으로 끄지 않습니다.

## 시나리오 1 처음 실행하고 발견 위치 등록

**상황:** Codex와 Claude Code를 사용하지만 어떤 스킬이 어디에 설치돼 있는지 모릅니다.

1. 환영 화면에서 로컬 검사와 파일 변경의 차이를 짧게 설명합니다.
2. 알려진 사용자 위치를 조회하고, 결과와 접근 오류를 위치별로 표시합니다.
3. 프로젝트 폴더를 선택하면 그 프로젝트 안의 알려진 스킬 위치를 추가합니다. 홈 폴더 전체를 재귀 탐색하지 않습니다.
4. 라이브러리에 설치 항목과 공유 관계를 표시합니다. 아직 관리 범위를 만들지 않습니다.

**인수 조건:** 스킬이 없어도 오류로 표현하지 않습니다. 접근 실패가 있어도 다른 위치의 결과는 남습니다. `다시 검사`, `위치 추가`, `Finder에서 확인` 중 필요한 행동을 제공합니다. 파일 변경은 0건이어야 합니다.

같은 실제 위치의 경로 별칭은 중복 등록하지 않습니다. 프로젝트의 작업 시작 위치와 저장소 루트를 구별해 저장합니다. 검사 한도·접근 실패로 결과가 일부라면 위치별로 표시하며, 확인하지 못한 참조 관계에 의존하는 변경은 허용하지 않습니다. 사용자 지정 등록으로 시스템·플러그인·조직·동기화 소유 정책을 우회할 수 없습니다.

## 시나리오 2 같은 이름과 공유 원본 구분

**상황:** `swiftui-ui-patterns`가 공용 폴더에 있고 Claude 폴더에는 그 원본을 가리키는 링크가 있습니다.

항목을 선택하면 두 설치 위치와 공유 원본을 연결해 보여줍니다. Claude 링크만 끄는 계획은 링크 하나를 보관하고 공용 원본은 유지합니다. 별도로 복사해 수정한 동일 이름의 스킬은 변형으로 표시합니다.

**인수 조건:** 같은 이름·같은 본문·같은 원본은 서로 다른 분류입니다. 본문 해시가 같아도 별도 폴더의 전체 자료가 같다고 주장하지 않습니다. 원본을 보관한 뒤에도 발견 위치에 남을 참조가 있으면 계획을 차단합니다. 보관된 참조를 복원하면서 원본을 보관하는 계획도 차단합니다. 이미 보관된 참조는 유지합니다. 미등록 위치의 참조는 찾았다고 주장하지 않습니다.

첫 버전은 다단계·순환 참조의 변경을 차단합니다. 이동 폴더 아래에 다른 등록 루트·범위 밖 설치 항목·보호 위치가 있는 경우도 차단합니다. 관련 항목은 관계를 확인하는 용도로 보여주고, 자동으로 관리 범위나 목표를 확장하지 않습니다. 사용자가 목표를 편집한 뒤 새 계획을 확인합니다.

## 시나리오 3 스킬 하나 끄고 다시 켜기

**상황:** Claude에서만 특정 스킬을 잠시 숨기고 싶습니다.

1. 상세에서 대상 설치 위치의 `보관하기`를 선택합니다.
2. 미리보기에서 원래 위치, 보관 위치, 영향받는 에이전트를 확인합니다.
3. `1개 항목 보관`을 선택하면 기록을 먼저 저장하고 실제 항목을 옮깁니다.
4. 완료 뒤 파일 상태와 대화 반영 안내를 표시합니다.
5. `원래 위치로 복원`으로 복원 계획을 확인하고 되돌립니다.

**인수 조건:** 링크는 링크 자체만 옮깁니다. 심볼릭 링크의 원본을 자동으로 이동하지 않습니다. 원래 위치에 다른 파일이 생겼으면 덮어쓰지 않습니다. 앱이 보관한 기록 없이 단순히 사라진 항목을 복구 가능으로 표시하지 않습니다.

전역 고정 항목의 보관 요청은 차단하고 고정 해제를 안내합니다. 정상 복원은 링크 원본의 승인·접근·가용 상태를 확인해야 합니다. 앱이 보관한 상대 링크는 보관 중 끊어져 보여도 문자열을 바꾸지 않으며 원래 부모 위치로 복원합니다.

## 시나리오 4 작업 프로필 구성하고 적용

**상황:** 앱 개발에 필요한 스킬과 글쓰기에 필요한 스킬을 전환하려 합니다.

그룹은 관련 항목을 모아두는 용도입니다. `앱 개발` 프로필에서 사용할 그룹과 개별 설치 항목을 고르고, 프로필이 관리할 범위를 별도로 정합니다. 고정 항목은 앱 전체에 저장하며 프로필마다 별도로 설정하지 않습니다. 적용 시 관리 범위 안의 고정 항목을 켜고, 범위 밖 고정 항목은 자동으로 복원하지 않습니다.

프로필 적용은 관리 범위 안에서 목표 항목과 고정 항목을 켜고 나머지를 보관합니다. 범위 밖의 항목은 그대로 둡니다. 미리보기에서 켜짐·보관·유지·변경 불가를 나눠 표시합니다.

**인수 조건:** 그룹끼리 겹쳐도 항목은 한 번만 처리합니다. 공유 위치를 변경해 다른 조회 범위에도 영향이 생기면 그 영향을 보여줍니다. 즐겨찾기는 보호 규칙으로 쓰지 않습니다. 차단 항목이 있으면 전체 적용을 막습니다. 첫 버전에는 부분 적용을 제공하지 않습니다. 사용자가 차단 사유를 해결하거나 관리 범위·목표를 편집한 뒤 새 계획을 확인합니다. 새로 설치된 항목은 기존 관리 범위에 자동 편입하지 않습니다.

## 시나리오 5 프로젝트로 범위 좁히기

**상황:** 현재 프로젝트의 스킬만 정리하려 합니다.

상단 조회 범위를 프로젝트로 바꿉니다. 해당 프로젝트에서 적용될 가능성이 있는 사용자·프로젝트 항목은 출처를 구별해서 보여줍니다. 프로필의 관리 범위는 화면 필터와 별개이며, 실행 전에 실제 변경 범위를 다시 표시합니다.

**인수 조건:** 조회 필터를 바꿨다고 숨겨진 항목을 끄지 않습니다. Codex의 저장소 조상 위치와 Claude의 중첩 위치를 똑같은 발견 규칙으로 취급하지 않습니다. 작업 시작 위치가 없거나 제품 버전 동작을 확인하지 못했으면 적용 가능성을 미확인으로 표시합니다.

사용자 위치의 변경은 `사용자 전역 — 다른 프로젝트에도 영향`으로 표시합니다. 프로젝트 A를 조회하고 있어도 사용자 전역 항목을 바꾸면 다른 프로젝트에 영향이 생깁니다. 미등록 프로젝트의 구체적인 사용 여부까지 확인했다고 표현하지 않습니다.

## 시나리오 6 플러그인과 시스템 스킬 조회

**상황:** 플러그인에 포함된 스킬의 내용을 확인하거나 검사를 하고 싶습니다.

상세에 제공 주체와 읽기 전용 이유를 표시하고 `본문 보기`, `Finder에서 보기`를 제공합니다. 복사본 가져오기는 1차 출시 뒤 별도 기능으로 구현하며, 새 사용자 위치와 이름 충돌을 미리 확인해야 합니다.

**인수 조건:** 플러그인 캐시·시스템·조직·계정 동기화 위치는 쓰기 권한이 있어도 첫 버전에서 직접 옮기거나 편집하지 않습니다. 관리 기능을 조용히 무시하지 않고 왜 불가능한지 설명합니다. 제공 주체가 갱신하면 검사 결과를 오래됨으로 바꿉니다.

## 시나리오 7 스킬 검사하고 수정

**상황:** 스킬 설명이 잘못됐거나 참조가 끊겼을 수 있습니다.

오프라인 검사는 형식, 필수·권장 메타데이터, 알려진 참조, 링크 상태를 확인합니다. 결과는 검사 규칙, 대상 에이전트, 근거 위치, 확인 시간을 포함합니다. Agent Skills 표준 검사와 에이전트별 허용 형식을 별도로 표시합니다.

초기 편집은 사용자 원본을 외부 편집기로 엽니다. 편집 완료를 자동 가정하지 않고 재검사합니다. 이후 앱 안에서 편집할 때에는 저장 전 원본 변경 여부를 확인하고 원본을 보존합니다.

**인수 조건:** Claude가 허용하는 메타데이터 생략을 모든 에이전트에서 실행 불가로 분류하지 않습니다. 자동 수정과 AI 리뷰는 기본 검사에 섞지 않습니다. 검사 과정에서 스킬에 포함된 명령이나 스크립트를 실행하지 않습니다.

## 시나리오 8 외부 변경과 오래된 계획

**상황:** 미리보기를 열어둔 사이 다른 도구가 스킬을 바꾸거나 플러그인을 갱신했습니다.

실행 직전에 계획의 대상과 참조 관계를 다시 확인합니다. 달라졌다면 `항목이 변경되었습니다. 다시 확인해 주세요`로 계획을 폐기하고 재검사합니다. 실행된 프로필이 실제 구성과 달라지면 `외부 변경 있음`을 표시합니다.

**인수 조건:** 외부 관찰에 따른 목록 갱신은 선택 항목과 검색어를 초기화하지 않습니다. 선택 항목이 사라지면 다른 항목을 자동 선택하지 않고 누락 상세·마지막 위치를 유지합니다. 사용자가 직접 필터를 바꿔 제외한 경우에는 선택 해제와 범위 안내를 제공합니다. 외부 편집 내용은 덮어쓰지 않습니다. 폴더 감시 알림만으로 상태를 확정하지 않고 실제 파일을 다시 관찰합니다. 본문뿐 아니라 참조 파일·링크 등 검사 근거가 바뀌면 관련 결과를 오래됨으로 표시합니다.

## 시나리오 9 적용 중 앱 종료와 복구

**상황:** 여러 항목을 바꾸는 도중 앱이 종료됐습니다.

다음 실행에서 미완료 기록을 읽고 각 이동의 출발·도착·진행 단계와 실제 결과를 확인합니다. 조회는 허용하지만 새 스킬 파일 변경은 막습니다. 확인된 이동을 작업 전 상태로 되돌리고, 충돌이면 복구 화면에서 원래 위치와 보관 위치를 함께 보여줍니다. 완료 기록은 저장됐지만 설정에 미반영된 경우도 재조정합니다.

**인수 조건:** 완료된 것으로 확인되는 이동만 역순으로 복구합니다. 복구 대상의 내용이 이후에 바뀌었거나 양쪽 모두에 파일이 있으면 자동 덮어쓰기를 하지 않습니다. 둘 다 없으면 데이터 손실 의심으로 명시하고 새 작업을 막습니다. 전체 일괄 변경이 하나의 파일 시스템 트랜잭션이라고 표현하지 않습니다.

중단 롤백은 작업 전 상태와 물리적 검증을 기준으로 합니다. 새 사용자 변경에 적용하는 고정 보호나 현재 링크 원본의 정상성 정책으로 롤백을 막지 않습니다. 이전에 끊어진 링크도 기록된 문자열과 위치를 검증해 작업 전 모습으로 돌릴 수 있으며 이를 에이전트가 사용할 수 있는 정상 복원으로 표현하지 않습니다.

이 예외는 새로운 물리적 위험을 허용하지 않습니다. 실행 후 새 참조가 생겨 역이동이 그 참조를 깨뜨리거나 파일·부모 위치·권한·목적지가 달라졌다면 롤백도 멈추고 복구 필요로 기록합니다.

충돌은 두 위치 열기·외부에서 정리·재관찰로 해결합니다. 자동 복구가 불가능하면 사용자가 현재 결과와 미복구·유실 여부를 명시적으로 확인하고 기록하는 수동 종료를 제공합니다. 기록과 재관찰이 완료돼야 복구 잠금을 해제하며 `복구 완료`와 `수동 해결·미복구 확인`을 구별합니다. 확인되지 않은 파일을 삭제하거나 덮어쓰지 않습니다.

## 시나리오 10 실행 중인 대화 확인

**상황:** 파일은 껐는데 에이전트가 기존 지침을 계속 따릅니다.

결과 화면은 `파일 변경 완료`를 표시하고, 새 대화에서 스킬 목록을 확인하는 안내를 제공합니다. 확인되지 않은 현재 대화의 반영 상태는 `미확인`입니다. 에이전트별 재발견 방식은 [호환성 계약](architecture.md#에이전트-호환성-계약)에 기록합니다.

**인수 조건:** 컨텍스트에서 제거했다는 문구를 사용하지 않습니다. 실제 에이전트의 버전과 시작 위치를 기록한 수동 검수에서 목록 변경과 기존 지침 잔존 여부를 별도로 확인합니다.

## 시나리오 11 그룹·프로필·고정 편집

**상황:** 새 작업 구성을 만들거나 기존 분류를 정리하려 합니다.

그룹·프로필 생성·편집·삭제와 고정 변경은 스킬 파일 변경 0건입니다. 그룹의 현재 구성원이 연결된 프로필의 목표에 반영되지만 자동 적용하지는 않습니다. 목표가 관리 범위를 벗어나면 오류와 프로필 편집을 안내합니다. 연결된 프로필이 있는 그룹은 먼저 연결을 해제해야 삭제할 수 있습니다. 프로필 삭제는 해당 구성을 저장 목록에서 지울 뿐 파일을 보관하거나 복원하지 않습니다.

고정은 앱 수준 `pinnedEntryIDs`에 저장합니다. 보관된 항목을 고정하면 `고정됨 · 현재 보관됨`을 함께 표시하며 파일은 옮기지 않습니다. 복원은 별도 미리보기로 요청합니다. 고정·목표·관리 범위를 바꾸면 이미 열린 계획을 다시 검증해야 합니다.

**인수 조건:** 고정 보호는 새 단일 변경·프로필 적용·완료 기록 되돌리기에 적용합니다. 고정 해제 없이 보관하는 새 계획은 실행하지 않습니다. 실행 또는 복구 중에는 고정·그룹·프로필·관리 범위 편집을 차단하고 이유를 표시합니다. 조회·즐겨찾기·외형 변경은 계속 허용합니다.

## 시나리오 12 위치 등록 해제와 보관 위치 관리

**상황:** 더 이상 조회하지 않는 프로젝트를 빼거나 보관 위치를 확인하려 합니다.

등록 해제는 해당 위치의 검사를 비활성화하는 행동입니다. 스킬 파일과 관련 작업 기록·항목 ID·원래 경로 정보는 삭제하지 않습니다. 보관 항목 또는 실행 중 작업이 있으면 등록 해제를 차단하고 복원이나 복구를 안내합니다. 비활성 위치가 포함된 새 변경은 재등록과 재관찰 후 계획을 만듭니다.

보관 위치에는 에이전트 위치에서 옮긴 실제 원자료가 있습니다. 캐시로 표시하거나 자동 정리하지 않으며 위치 열기와 전체 복원 미리보기를 제공합니다. 첫 버전은 보관 항목이 남은 위치의 변경·이관과 일괄 초기화를 제공하지 않습니다. 설정이 손상되면 기록과 보관 항목을 재연결하는 복구를 안내하고 임의로 새 빈 상태로 덮어쓰지 않습니다.

**인수 조건:** 실행·복구 중 발견 루트와 보관 위치 설정 변경은 차단합니다. 외형·즐겨찾기·조회는 허용합니다. 기록과 원자료의 보존을 앱 제거 후 데이터 삭제까지 보장한다고 표현하지 않습니다.

## 시나리오 13 실행 중 중단과 창 닫기

**상황:** 적용을 시작한 뒤 중단하거나 메인 창을 닫으려 합니다.

준비 중 `취소`와 Escape는 계획을 닫으며 파일 변경은 0건입니다. 실행 중에는 `중단 요청`을 제공하며 다음 이동 전 멈추고 완료된 이동의 롤백으로 이어집니다. Escape로 실행 화면만 단순히 닫지 않습니다. 중단 요청은 되돌리는 중·중단 완료·복구 필요까지 상태를 알립니다.

메인 창 닫기는 실행 취소가 아닙니다. 창을 다시 열면 같은 작업의 진행·결과를 볼 수 있습니다. 앱 종료 요청은 안전한 중단·기록 경로를 거친 뒤 종료하며, 강제 종료는 다음 실행의 복구로 처리합니다. 메뉴 막대와 설정 창에서 두 번째 실행 경로를 만들지 않습니다.

**인수 조건:** 실행 중 적용 버튼의 중복 실행을 막고 작업마다 한 번만 적용합니다. 안전 조건에 영향을 주는 설정은 실행·복구가 끝날 때까지 편집할 수 없습니다.

## 시나리오 14 완료 기록 되돌리기

**상황:** 이전에 완료한 파일 변경을 되돌리려 합니다.

완료 기록 되돌리기는 새 사용자 변경 의도입니다. 대상 항목의 기록된 실행 후 상태와 현재 상태를 재검증하고, 이후 같은 항목을 바꾼 작업·외부 수정이 있으면 차단합니다. 후속 변경을 침범하는 과거 상태 강제 복원은 제공하지 않습니다. 고정 보호·정상 복원 검증을 거친 새 미리보기를 확인해야 실행할 수 있습니다.

**인수 조건:** 중단·실패 직후 자동 롤백과 완료 기록 되돌리기를 별도 행동과 결과로 표시합니다. 후속 변경이 있으면 현재 구성에서 새 목표를 만들도록 안내합니다.

## 시나리오 15 출처 저장소로 정리하고 작업 구성에 연결

**상황:** 여러 저장소에서 가져온 스킬을 출처별로 찾고, 그중 일부를 앱 개발 구성에 포함하려 합니다.

1. 설치 목록의 `출처` 필터에서 저장소를 고릅니다. Codex·Claude의 설치 위치를 구별하고 설치 방식·관리 주체·출처 근거를 확인합니다.
2. 출처 근거가 없는 항목은 `출처 미확인`으로 둡니다. 사용자가 저장소를 연결하면 `사용자 지정`으로 표시합니다. 저장소를 등록하는 것만으로 설치를 시작하지 않습니다.
3. 원하는 설치 항목을 선택해 `선택한 설치 항목으로 그룹 만들기`로 분류를 저장합니다. 다른 저장소의 항목도 같은 그룹에 추가할 수 있습니다.
4. 작업 구성 편집에서 이 그룹을 목표에 연결합니다. 관리 범위 밖이면 범위를 편집하도록 안내하고, 제공자 관리 항목이면 파일 변경 불가 사유를 표시합니다.
5. 변경 검토에서 실제 보관·복원과 영향을 확인한 뒤 적용합니다. 출처별 보기와 그룹 생성까지는 파일 변경 0건입니다.

**인수 조건:** 저장소 필터는 관리 범위와 목표를 바꾸지 않습니다. 출처 근거와 설치 방식은 설치 항목별로 기록하며 수동 연결은 관리 권한을 부여하지 않습니다. 같은 출처라도 사용자 복사본과 플러그인 항목을 합치지 않습니다. 출처 정보가 없다고 조회·검증 가능한 사용자 항목의 보관을 막지는 않습니다. 등록한 저장소의 로컬 설치 항목이 0개이면 `현재 등록 위치에서 발견된 항목 없음`으로 표시하며 원격 총수를 추정하지 않습니다.

그룹 생성은 선택한 ID만 저장합니다. 이후 같은 저장소에서 새 스킬을 설치해도 기존 그룹·프로필에 자동 추가하지 않습니다. 출처 연결을 해제해도 파일·구성·변경 기록은 보존합니다. 출처 분류만 수정한 경우 기존 파일 변경 계획의 안전 조건은 유지되며, 그룹·프로필 편집은 기존 재검증 규칙을 따릅니다. 비공개 저장소와 오프라인 상태를 출처 없음이나 삭제됨으로 단정하지 않습니다.

## 첫 출시 인수 기준

| 검수 항목 | 통과 조건 |
| --- | --- |
| 조회 | 접근 실패·없음·보관됨·읽기 전용·활성 미확인을 구별 |
| 전환 | 사용자 폴더와 링크만 계획된 위치로 이동, 기존 파일 덮어쓰기 0건 |
| 프로필 | 지정한 관리 범위 밖 변경 0건, 새 사용자 의도에서 전역 고정 항목 보관 0건, 차단·미검증 상태를 구성 일치로 표시하지 않음 |
| 출처 분류 | 수동 연결의 권한 상승 0건, 저장소 필터로 파일·목표·범위 변경 0건, 새 항목의 그룹·프로필 자동 편입 0건 |
| 복구 | 항목 이동마다 중단해 재실행해도 파일과 링크 내용 보존 |
| 수동 해결 | 재관찰·결과 확인·기록 없이 잠금 해제 0건, 미복구를 성공으로 표시하지 않음 |
| 설정·CRUD | 원자료 변경 0건, 비활성 등록의 기록 보존, 실행·복구 중 안전 조건 편집 차단 |
| 외부 변경 | 오래된 계획 차단, 수정된 복구 대상 자동 이동 차단 |
| UI | 키보드만으로 조회·미리보기·취소·적용·복구 가능 |
| 호환성 | 지원 에이전트별 실제 스킬 재발견과 버전 기록 |
| 개인정보 | 기본 실행에서 네트워크 전송 0건, 지침 실행 0건 |

본 명세 반영과 시안 정합성 검사를 완료하면 읽기 전용 발견과 임시 폴더의 쓰기 코어 구현을 시작할 수 있습니다. 실제 사용자 스킬의 쓰기는 보관·복원·롤백 각각의 중단 경계, 충돌·외부 변경·볼륨·공유 영향에 대한 실제 파일 테스트를 통과한 뒤 연결합니다. 시안 정합성 검사는 이 조건을 대신하지 않습니다. 새 UI의 레이아웃과 스타일 설계는 코어 검증과 병행할 수 있습니다.

## 후속 기능

AI 리뷰는 명시적으로 선택한 본문만 보내고 요청 미리보기와 실패 기록을 제공하는 별도 단계입니다. 팀 동기화, 원격 설치, 자동 프로필 선택, 개별 플러그인 설정 변경은 사용자 수요와 공식 지원 방법을 확인한 뒤 설계합니다.
