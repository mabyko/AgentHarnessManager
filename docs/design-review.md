## 시안 검증

```sh
node scripts/check-design.mjs
```

검사는 계획 입력을 직접 호출하고 시안의 적용·기록 되돌리기·목록 갱신 행동을 메모리 DOM에서 실행합니다. 단일 요청·프로필·차단·변경 없음·입력 충돌·참조 관계·상태 표시를 확인합니다. 테스트는 실제 사용자 스킬을 읽거나 이동하지 않습니다.

시안의 복구 함수는 기록된 from/to의 관찰 분류만 검사합니다. 실제 영속화와 파일 이동·복구 전체 안전성을 입증하지 않습니다. 수정 중간의 검사 실패를 완료 판정으로 사용하지 않습니다.

### 수정 후 재검토 결과

- `node scripts/check-design.mjs`와 `node --check docs/design/preview-model.js` 통과.
- 파일 안전성 검토자가 수정된 본 명세의 고정·원형 복구·신규 참조·설정 재조정·방향·등록 정보 수명을 대조했고, 발견한 manifest 이름 충돌도 payload 분리로 수정한 뒤 확인.
- 제품 검토자가 열린 Undo의 늦은 차단과 검사 결과 화면의 외부 누락·결과 0건 전환을 재현 입력으로 재검증. 차단 근거·적용 비활성·다시 확인과 선택·마지막 위치 유지 확인.
- Chrome DevTools에서 고정 항목 보관 차단, 글쓰기 프로필의 예시 적용, 열린 Undo의 외부 수정 차단을 확인. 최신 시안의 전체 위치 접근성 이름, 960 px에서 가로 넘침 없음, JavaScript 콘솔 오류 없음 확인.

이번 검토 범위에서 미해결 명세 충돌이나 시안의 재현 반례는 남기지 않았습니다. 실제 파일·영속화·에이전트·네이티브 접근성 검증은 아래 코어 구현 조건으로 남습니다.

## 새 UI에서 유지할 계약

### 최종 후보의 한 차례 병렬 검토

후속 색상 피드백: 아래 병렬 검토는 사용 흐름·상태·정합성 확인이며 녹색 팔레트가 최선이라는 판단 근거는 아니다. 사용자가 넓은 녹색 면적을 지적한 뒤 후보의 바탕·선택 영역을 무채색으로, 행동 강조를 파란색으로 바꾸고 녹색을 상태 역할로 분리했다. 이 색상 조정에 추가 서브에이전트 라운드를 진행하지 않았다.

2026-10-01. 사용자 요청으로 세 에이전트가 제품 UX, 시각·접근성, 명세·실행 시안 정합성을 한 차례 병렬 검토했다. 부모 에이전트가 의견을 종합하고 수정했다. 추가 재검토 라운드는 진행하지 않았다.

세 관점 모두 차분한 중성·녹색 스타일, 작업 구성 중심 첫 화면, 출처와 관리 주체의 분리를 유지하도록 제안했다. 설치 목록의 출처 필터를 별도 저장소 화면으로 확장하거나 영구적인 세 번째 상세 열을 만드는 대신 현재 흐름을 다듬었다.

| 발견한 문제 | 반영한 수정 |
| --- | --- |
| 그룹 상세에서 작업 구성으로 이동하면 빈 모달이 남음 | 명시적 화면 이동 때 상세 모달을 닫음 |
| 구성의 스킬 확인이 설치 목록으로 넘어가며 맥락을 잃음 | 현재 구성·검색·조회 상태를 유지하는 상세 보기, 닫기 후 항목으로 포커스 복원 |
| 저장소 검색어가 다른 화면까지 적용됨 | 화면 이동 때 검색 초기화, 관찰·재검사 때 보존 |
| 결과 수가 상태·검색 필터를 반영하지 않음 | 표시 수와 출처 범위 총수 분리, 설치 경로 검색 지원 |
| 좁은 창에서 설치 위치 열이 사라짐 | 이름 아래에 에이전트와 경로를 다시 배치 |
| 유지와 변경이 작은 문구 차이에 의존 | 실제 변경 행에 전후 상태·아이콘·강조, 유지 행 중립색 |
| 적용되지 않는 에이전트 조회 필터와 모달의 배경 검색 단축키 | 구성·기록의 필터 비활성화와 이유 안내, 모달의 전역 검색 가드 |
| 다이얼로그 하단 높이를 고정값으로 가정 | 세로 flex 배치로 본문만 스크롤, 하단 행동 보존 |

기존 메모리 DOM 검사는 실제 브라우저의 버블링·close 이벤트·요소 존재를 모두 모사하지 않는다. 가짜 노드의 포커스 요청 성공을 실제 포커스 복원으로 해석하지 않는다. 이번에는 모달 열림·닫힘, 탐색 맥락, 검색·개수·변경 전후에 대한 회귀 검사를 추가했다. Chrome DevTools의 별도 검토 세션에서 구성 내부 상세·즐겨찾기 후 본문 보존·Escape 닫기와 실제 항목 포커스, 그룹→구성의 모달 닫힘과 새 화면 포커스, 표시 수 1/3, 모달의 배경 검색 가드를 확인했다. 960×640 px에서 사이드바를 열어도 두 SwiftUI 항목의 에이전트·경로가 보였고 가로 넘침은 없었다. 같은 크기의 긴 변경 검토는 본문만 스크롤하고 취소·적용 버튼과 모달 내부 포커스를 유지했다. 예시 적용 후 파일 목표 일치·기록 1건·구성 검토 버튼으로 포커스 복원을 확인했고 JavaScript 콘솔 오류는 없었다. 밝은·어두운 기본 화면과 설치·출처·변경 검토 이미지를 갱신했다. 실제 파일·네이티브·최초 실행·편집 CRUD 검증을 대체하지 않는다.

| 유지할 의미 | 교체 가능한 표현 |
| --- | --- |
| 설치 위치·관리 주체·파일 상태와 대화 반영 구분 | 열 수, 사이드바, 행·카드, 요약 타일·배지 |
| 그룹·프로필 편집과 파일 변경 구분 | 메뉴 계층, 화면 통합, 탐색 방법 |
| 실행 전 정확한 대상·경로·영향·차단 사유 확인 | 시트, 단계형 화면, 상세 패널 |
| 실행·중단 요청·복구·수동 해결 상태 구분 | 진행 화면, 알림, 기록 배치 |
| 실제 설치 대상을 지정하고 다른 복사본을 합쳐 변경하지 않음 | 스킬별 묶음 카드. 묶음 안에서 실제 설치 위치 선택 |
| 키보드·VoiceOver로 주요 행동 완료 | 아이콘, 색상, 글자, 간격, 창 크기와 애니메이션 |

UI는 사용자의 명시적 의도를 전달하고 코어의 계획을 보여줍니다. 이유 문구나 첫 선택 항목에서 새 목표를 추론하지 않습니다. 새 스타일은 기존 시안의 CSS·토큰·3단 배치를 그대로 사용할 의무가 없습니다. 카드 수와 설치 항목 수는 단위를 구별합니다.

## 코어 구현에서 통과해야 하는 조건

- 실제 임시 폴더에서 보관·복원·역이동 각 기록·이동 경계에 종료를 주입하고 재실행해 자료 보존 확인.
- 목적지 충돌·원본 교체·후속 편집·신규 참조·동시 앱 실행·볼륨 접근 실패 검증.
